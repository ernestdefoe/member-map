# Member Map: working rules

- **Commit straight to `main` and push. Never open a pull request on this repo.** Commit subjects are conventional (`feat:`, `fix:`); the release drafter bumps from the subject.
- `js/dist` is committed and is what forums load. After any change under `js/src`, run `npm run build` in `js/` (from a fresh `npm ci`) and commit the bundle; CI fails if it is stale.
- Publishing a release is Ernest's click. Nothing is announced until he says so.

## Design rules that exist for a reason

- **Privacy is enforced on the server.** A saved location is the centre of the named place (city, region or country) around the point the member chose, looked up by `Geocoder::place()` and rounded (`Precision::decimals`). The raw point is never stored or returned. Never add a path that saves client coordinates directly.
- **Nominatim's usage policy**: max one request a second for the whole forum (cache lock + timestamp in `Geocoder::throttle`), an identifying User-Agent, every answer cached 30 days in `member_map_geocode` (pruned on write, not by the file cache, which never deletes expired keys), and **no search-as-you-type**: the form searches only on the button or Enter.
- Geocoding happens only when a member searches or saves. Never call it while rendering a page.
- The map endpoint is ONE query (`MemberQuery`): visibility, confirmed email, the `member-map.list` permission (checked in SQL via group_permission/group_user, so losing it takes someone off the map at once) and suspension.
- `memberMapLocation` / `memberMapOwn` on the user resource are deferred values batched per request (`Api\UserFields`): one query for every user on the page. Keep state keyed by the request in the WeakMap.
- The map engine is MapLibre GL 6 (OpenFreeMap vector styles; raster tiles as the fallback), the `forum/map/engine` chunk, imported dynamically. A STATIC import of it from two chunks makes webpack emit a numbered root chunk that `jsDirectory` does not publish (404). MapLibre 5.x has a critical sanitizer advisory: stay on 6.
- MapLibre 6 needs its module worker. 🚨 It is bundled INSIDE the engine chunk as a string (`?worker-source` → `js/scripts/worker-source-loader.cjs`) and `engine.prepare()` starts it from a blob. Never ship it as a separate file again: a forum left `maplibre-worker.js` unpublished (404, blank map, reported by Claudius 2026-11-12). The loader drops the worker's `//# sourceMappingURL` comment because Flarum strips that comment to end-of-line from every chunk, which would cut the one-line string. `MapAssetsTest` guards both. Await `prepare()` before creating a map; if the engine can't start, the page shows the list with a note (`mapFailed`).
- Its CSS is injected by the chunk (`map/mapCss.ts`, generated by `scripts/map-css.mjs`), not in forum.less.
- 🚨 Flarum sends `Referrer-Policy: same-origin`, so tile requests carry no Referer and OpenStreetMap answers with an "Access blocked" picture. The engine's `transformRequest` and the profile mini-map's `<img referrerpolicy>` send the origin.
- MapLibre writes `transform` on a marker's element: our buttons sit inside a `.MemberMapMarker` wrapper so hover zoom and the drop-in animation never fight it.
- `map.loaded()` stays false while any tile loads: use our own `ready` flag (set on the first `load`). The globe's zoom is the Mercator zoom at the centre's latitude: size it with cos(lat).
- Time zones are worked out OFFLINE (`Timezones`): the browser's zone when it belongs to the place's country, else the state's zone by ISO code (`RegionZones`: US, CA, AU), else PHP's zone data scored by distance + offset.
- Trips notify members within 160 km (`Trips::notify`, bounding box + distance, max 50). Meetups start a discussion through Flarum's API as the member (process() skips `startDiscussion` and the tag check: both are asked by hand) and go on Calendar when it's enabled.
- The map endpoint refuses crawlers (`Api\Crawlers`) and the page is noindex unless the admin allows it. `members_only` places never reach guests (map or profile).
- Marker and popup content is built with DOM text / Mithril, never HTML strings: names must never become HTML.
